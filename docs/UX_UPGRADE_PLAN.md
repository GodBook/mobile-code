# Mobile Code 用户体验优化与升级规划

审查日期：2026-10-13（Asia/Shanghai）。基线：已发布的 **0.2.3 / versionCode 6**，本地审查提交 `3a0846880bb1350a6bb39717e104a5d441cd07c0`。

本文最初根据现有代码、项目规格、验收记录及亮暗主题截图形成升级建议，不替代 [SPEC.md](project/SPEC.md) 中已批准的要求。用户随后授权执行本计划、连接手机测试并更新GitHub/Release。已发布[v0.3.0](https://github.com/GodBook/mobile-code/releases/tag/v0.3.0)，完成UX-01～UX-14的核心实现，正式APK真机43/43通过；实际范围与未覆盖项目见[更新说明](releases/v0.3.0.md)、[验收报告](../verification/releases/v0.3.0/acceptance.json)、[STATE](project/STATE.md)和[TASKS](project/TASKS.md)。下面的“现状”与源码索引保留原审查基线。

## 1. 判断与升级方向

当前项目已经具备本地 IDE 的核心能力：四语言离线编译运行、真实调试、跨文件语义补全、自动保存、不可变运行快照和 GitHub 更新。0.2.3 也已交付亮暗主题、语法配色和大文件性能修复。下一步最值得投入的是让用户更容易找到文件、确认保存状态、处理输入输出，并在异常后继续工作。

建议按“数据与反馈 → 编辑效率 → 调试与项目能力”推进。沿用 Compose / Material 3 / Sora 和现有配色，在实际操作上降低成本，不安排整套视觉重做。

| 体验环节 | 当前已有能力 | 本轮审查发现的主要空间 |
|---|---|---|
| 开始使用 | 首页、新建、语言筛选、ZIP 导入、离线资源进度 | 首页占用较大；已有项目时缺少紧凑布局；准备失败的恢复入口在设置中 |
| 管理项目 | 最近项目列表、私有存储、SAF 导入导出 | 缺少名称搜索、置顶、重命名、复制、可恢复删除；异常项目不在列表显示 |
| 编辑代码 | 多标签、折叠、撤销重做、查找替换、中文输入、亮暗主题 | 文件列表为平铺路径；缺少快捷打开、行跳转和跨文件搜索；重启只恢复一个文件 |
| 确认保存 | 500ms 空闲保存、原子写入、失败保留脏缓冲区 | “正在保存”同时覆盖等待保存和保存失败，错误提示缺少持续处理入口 |
| 运行程序 | 参数、预置/交互输入、EOF、输出通道、停止、资源限制 | 输入发送结果与草稿脱节；显示尾部截断缺少说明；历史和生成文件没有可见入口 |
| 调试程序 | 真实断点、单步、栈、变量、只读观察、快照导航 | 图标学习成本高；断点失败原因不易查看；变量详情与观察恢复可加强 |
| 更新软件 | 版本说明、大小、进度、后台下载、取消、签名校验 | 可增加下载前空间说明、网络偏好、最后成功检查时间与安装后结果提示 |

### 已有证据与边界

- 0.2.3 历史验收记录为最终 APK 真机回归 **29/29**；设备为小米 9 SE、Android 15、ARM64、4KiB 页。本文引用这些结果，没有复跑。
- 历史 1MiB 文件打开为 **431.855ms**，80 次输入的下一帧回调 P95 为 **30.795ms**；这不是物理 IME 到显示的完整输入时延。应用 PSS 也不包含全部语言服务进程。
- **16KiB 实际运行、Android 10～17/厂商覆盖、长期后台和低内存矩阵、外部 SAF 提供方 UI 矩阵**仍待验证。ELF 对齐审计不能代替 16KiB 执行验收。
- 0.2.2 有真实 GitHub 下载及系统安装器升级证据；0.2.3 仅验证覆盖安装数据保留与公开更新检查，不能合并称为 0.2.3 OTA 全流程通过。

详见 [验证记录](VERIFICATION.md) 和 [当前检查点](project/STATE.md)。

## 3. 第一批：让异常可理解、可恢复

### UX-01：保存状态与恢复

**现状。** 保存已经采用临时文件、同步和原子替换；保存抛错时脏文档仍保留。工作台只要存在脏文档就显示“正在保存”，具体失败信息经通用 Snackbar 展示后清除，因此用户无法持续确认某个文件尚未写入。[证据 E01]

**建议。** 按文件记录“待保存 / 保存中 / 已保存 / 保存失败”，保存失败时在标签与状态区域保留提示，提供“重试”和“导出未保存内容”。导出未保存内容必须读取当前缓冲区，并走独立恢复路径：现有导出方法先调用 `saveAll()`，写入故障时也会被阻断。显示上次成功保存时间；失败时保持编辑和复制可用。

在原子保存之外评估轻量恢复草稿，主要覆盖用户尚未等到 500ms 保存就发生进程终止的窗口。恢复草稿与正式源文件分开，启动后让用户比较并选择，不自动覆盖较新的文件。磁盘已经写满时无法保证草稿落盘，界面必须如实说明。

**验收。** 注入写满、写入失败、快速连续编辑和进程重建；原文件不被破坏，脏标识不被清除，重试只将成功写入的文档版本标为已保存。导出失败缓冲区不依赖原项目目录可写。运行和安装更新必须等保存成功；恢复时不能把旧草稿静默覆盖到新源码。

### UX-02：标准输入、发送结果与 EOF

**现状。** 发送按钮和键盘发送操作先启动异步发送，再立即清空输入框；输入区域按 `session.active` 启用，而 active 还包含准备、编译、启动和调试暂停。`eof()` 关闭管道后，UI 没有独立的 stdin 关闭状态。[证据 E02]

**建议。** 将“管道已建立 / 可发送 / 发送中 / 已关闭”作为会话能力暴露给 UI；成功写入后再清除对应草稿，失败保留并显示原因，重复点击在发送期间禁用。EOF 改为“结束输入（EOF）”，执行后显示“输入已结束”，新会话再重置。调试暂停期间是否允许发送必须有清楚的规则和测试。

使用“可发送输入”描述管道能力；仅凭进程运行、长时间无输出或管道打开，不能断言程序正在等待用户输入。预置输入展示只读预览，并说明发送完后会关闭输入。

**验收。** 准备/编译期间不允许向未建立管道发送；管道关闭、停止任务、发送异常时草稿保留。发送过程中用户继续输入的新草稿不能被旧请求成功回调清空；EOF 幂等，下一次运行能重新输入。四语言均检查交互输入、预置输入和调试状态切换。

### UX-03：异常项目可见，导入失败可恢复

**现状。** 项目扫描对读取或校验失败使用 `runCatching(...).getOrNull()`，异常目录不会出现在首页。ZIP 导入在隐藏暂存目录中解压，出错时没有显式的清理/恢复收尾；语言无法唯一确定时直接拒绝。[证据 E03]

**建议。** 扫描返回有效项目和异常条目，异常条目显示原因及“重试 / 导出原目录 / 查看恢复说明”，确认目录仍在后再提示“原文件仍保留”。不要自动创建空配置去覆盖损坏配置。导入增加进度、取消和结果说明；多语言或入口不明确时允许用户选择配置，同时保留原有 ZIP 路径和大小校验。

失败暂存目录由导入任务身份管理，可明确标记并在用户确认后清理；恢复与清理不得涉及既有项目。导入成功仍只打开项目，不自动执行代码。

**验收。** 损坏/未知版本 `project.json`、多根目录 ZIP、混合语言、超限文件、路径越界、读流中断及取消均有明确结果；原项目与原 ZIP 保留。重试不会生成重复项目；异常项目可以导出可读取的原始内容。

### UX-04：首次准备与组件失败反馈

**现状。** 已有校验、解压与原生组件校验阶段和进度，资源准备期间也能编辑；首页展示状态，工作台展示一行状态，重试入口在设置中。运行按钮未就绪时禁用，但其附近缺少直接的恢复入口。[证据 E04]

**建议。** 提供可展开的组件状态区，显示当前阶段、已处理大小、失败原因、“继续编辑”和“重新检查”。在按钮附近说明“本地组件尚未就绪”；从恢复的项目直接进入工作台时也能查看准备状态。存储不足要显示实际可用量及所需量，不能用虚构倒计时掩盖未知耗时。

**验收。** 首装、已准备后的启动、升级后重检、资源损坏、存储不足和准备中重建界面均可理解；不会重复解压或因重试破坏正在使用的组件；准备期间新建和编辑保持可用，准备完成后按钮与真实状态一致。

### UX-05：存储管理与会话产物

**现状。** 每次运行生成独立源码快照、编译目录、工作目录和日志；当前代码中未发现会话目录保留策略。导入暂存目录、按资源哈希区分的旧工具链目录也缺少统一的容量展示和清理入口。日志有单次上限，不等于历史总容量受限。[证据 E05]

**建议。** 先建立存储盘点，分别显示项目、历史快照/产物、语言索引、导入暂存和更新包的实际大小。提供用户触发的分类清理，列出范围和预计释放量；项目源码、当前组件、活动会话及仍被预览引用的快照排除在缓存清理之外。读取到的用户生成文件应先提供浏览与 SAF 导出，再决定保留或删除。

历史会话保留数量/容量的默认值需根据实测决定；自动清理只面向已明确告知的可重建缓存，不能把尚未导出的用户生成文件一并归为缓存。新一轮运行前检查可用空间，空间不足时说明如何处理，不替用户删除项目。

**验收。** 连续运行至少 100 次后盘点准确，清理不会破坏源码、当前会话、可见快照或正在下载的更新。活动任务期间禁止相冲突的清理；强制结束后遗留目录有可识别状态。失败及取消的清理不会误报完成，历史列表能正确处理已清理产物。

## 4. 第二批：缩短手机上的编辑路径

### UX-06：首页更快回到项目

**现状。** 无论有无项目，首页都展示较大的介绍区域；已有语言筛选和最近项目，但无名称搜索、置顶或最近使用时间，筛选无匹配时没有专门的空状态。[证据 E06]

**建议。** 首次使用保留简短介绍与离线示例入口；已有项目时压缩介绍，将“继续上次项目”和列表放前。增加名称搜索、置顶、最近打开时间及筛选空状态。区分“最近打开”和“最近修改”，不要把保存时间直接显示为打开时间。

**验收。** 100 个项目下输入搜索与切换筛选不卡顿，中文名称可检索；无匹配时能清除条件。置顶、排序及继续入口重启后保持；首页空状态与组件准备状态不会挤掉主要按钮。

### UX-07：目录树与安全管理

**现状。** 文件浏览器用相对路径平铺全部文件，支持打开与新建；工作台缺少目录折叠及文件/项目重命名、移动、复制和删除入口。[证据 E07]

**建议。** 显示可折叠目录树，支持定位当前文件、文件搜索和路径面包屑。文件操作集中到长按/更多菜单，输入时直接显示路径冲突等校验错误。删除进入应用内回收区，提供撤销和明确保留策略；项目删除单独说明范围。

文件移动前保存，原子迁移成功后更新标签、光标、断点、运行入口和语言服务文档状态；Java 类名与文件名的语义重命名单独处理。活动会话内先限制移动/删除等高风险操作，保持当前快照规则。新增元数据需要 Room 迁移验证，不能靠删除数据库解决。

**验收。** 中文/emoji 路径、同名不同目录、冲突、空间不足、撤销删除及重启恢复均正确；失败时原路径和脏缓冲区保留。重命名/移动后构建、补全与断点有效；不会将简单文件重命名称为跨项目符号重构。

### UX-08：快捷导航与内嵌搜索

**现状。** 查找替换通过 AlertDialog 执行，仅提供固定搜索选项，无结果计数；缺少工作台中的按文件名打开、按行跳转和项目文本搜索入口。[证据 E08]

**建议。** 文件内查找改为紧凑工具条，保持当前匹配可见，显示“第 n / 共 m 处”，增加大小写、整词及可选正则。增加快捷打开与“转到行”，项目搜索按文件分组展示命中，支持源码根/文件类型范围和取消。跨文件替换后续再做预览与确认，先交付可靠的只读搜索。

**验收。** 中文、emoji、CRLF、无结果和非法正则有明确行为；中文组合输入不被搜索抢焦点打断。后台搜索可取消，过期结果不覆盖新结果，搜索默认排除工具链、索引和会话目录；替换仍遵守调试只读，撤销能恢复内容。

### UX-09：恢复完整编辑上下文

**现状。** 同一工作台中有多标签及编辑器实例缓存；持久化设置只记录最后项目、文件和一个光标位置，启动选择项目时只打开一个文件。观察项保存在 ViewModel 内。[证据 E09]

**建议。** 按项目保存打开标签顺序、活动标签和每文件光标/滚动位置，提供“关闭其他 / 关闭已保存 / 重新打开关闭标签”。恢复内容以磁盘源文件为准；缺失文件给说明，不创建空文件。观察表达式可按项目恢复，变量值必须重新请求；折叠范围需等新解析结果后恢复。

不把完整文本和无限撤销栈塞入 DataStore，也不承诺跨进程完整撤销历史。大文件与过多标签采用容量预算，回收可重建的编辑器视图前保存光标，保留尚未成功保存的内容。

**验收。** 5～10 个混合大小文件，切换、旋转、重启及文件缺失后顺序与位置合理；已有的关闭标签释放和快照释放验证继续通过。恢复不会将旧内容覆盖到磁盘或应用旧诊断。

### UX-10：小屏、输入与可访问性

**现状。** 已按工作台高度收起辅助区，并为紧凑控制台提供独立面板；横屏零编辑区问题已在 0.2.3 修复。仍有按固定阈值隐藏快捷栏、状态区使用 10sp 等可改善点。标签关闭图标布局尺寸为 20dp，且嵌套在可点击标签内，实际触控扩展范围与误触需专项检查。设置仅有亮/暗两种主题，默认超时通过 1～600 的滑杆配置。[证据 E10]

**建议。** 保持现有配色，增加明确的“专注编辑”入口、可调整字号的状态/控制台和语言相关快捷键排列；为关闭标签等动作提供至少 48dp 的可触控区域。常用符号按语言调整，增加可选上/下移动、缩进/反缩进；检查 Sora 已支持的硬件快捷键，补应用级导航与帮助，避免重复绑定。

设置按外观、编辑、运行、组件、更新分组；可新增“跟随系统”且保留原亮/暗设置迁移。超时提供数字输入与常用值，明确“新项目默认值”和“当前项目设置”区别。为运行/调试/单步提供长按说明及 TalkBack 标签，控制台展开/收起的标签跟随实际操作改变；不要求用户只靠颜色辨别断点或错误。

**验收。** 360dp 级窄屏、横竖屏、分屏、系统字体 1.0/1.3/1.5 倍及键盘开合下，编辑区始终可用，关键操作可达。中文 IME、emoji、外接键盘、TalkBack 焦点与返回路径逐项检查。新增动画短且可关闭，不在输入/运行输出时引入持续装饰动画。

### UX-11：问题、日志与运行配置

**现状。** 已分 stdout/stderr/编译通道，支持复制、错误跳转、运行参数和预置输入。UI 仅显示当前通道末尾 32,000 字符；内存通道和磁盘日志也有各自上限，复制读取的是内存内容。问题列表直接合并实时诊断与运行诊断；数据库有历史记录但无用户入口。运行配置虽然接收文件列表，入口仍靠手写。[证据 E11]

**建议。** 输出区标注显示/保留范围，提供暂停跟随、回到底部、当前视图清空、查找和日志导出；“清空视图”不能静默删除磁盘日志或停止排空管道。历史日志达 10MiB 后也不能宣称可导出完整无限输出。生成文件入口与 UX-05 共用保留/清理规则。

问题按文件、严重度和来源筛选，区分“当前文档分析”与“本次运行快照”，仅在路径、版本/快照、位置和消息等身份一致时去重。保留已有快照导航，修正代码后不能让旧运行错误伪装成当前错误。

运行配置增加有效入口候选、参数数组预览和输入示例；多个测试输入可作为后续项目配置预设，空字符串参数也需能准确表达。历史入口显示时间、语言、结果、耗时和产物可用状态，不自动重放可能有副作用的用户程序。TIMEOUT、MEMORY_LIMIT、OUTPUT_LIMIT 在中文说明下保留原始原因及处理入口。

**验收。** 12MiB 输出仍持续排空且编辑可用，用户能理解截断并导出已保存日志；切换通道不丢状态。编辑后旧诊断能打开正确快照，当前分析不被错误合并。参数含空串、空格、中文和 emoji 时不经 shell 拆分；历史显示不意味着任务被自动重试。

## 5. 第三批及专项优化

### UX-12：让真实调试更容易使用

**现状。** 已有真实断点绑定、单步、栈、变量和只读观察；断点结果含 message，编辑器用符号表达状态，但缺少集中查看原因的入口。变量行主要显示名称与截断值，展开最多三层；观察项没有跨启动恢复。[证据 E12]

**建议。** 增加断点列表，显示请求行、实际绑定行、待验证/有效/失败及原因，支持跳转与移除。暂停时显示当前文件/行和所选栈帧；变量详情可复制完整可用值及类型。观察表达式按项目保存，明确只读与允许的语法；调试只读状态提供“停止后编辑”入口。

变量子树的异步加载绑定会话 ID、暂停序号及栈帧，继续或再次暂停后旧请求不更新新界面。现有展开缓存主要以变量引用和名称记忆，这一场景应专项验证，不能仅凭静态审查就断言已发生错值。

**验收。** 无法绑定、绑定到相邻行、切栈帧、反复单步、重新调试和服务退出均有可信状态；新暂停中不显示旧变量子树。四语言独立验收；Python 仍明确主线程调试范围，不增加任意求值、变量修改或方法调用。

### UX-13：代码导航与语言服务体验

**现状。** 当前语言服务桥接提供补全、签名和诊断；未发现定义、引用、文档大纲及格式化的应用入口和对应请求。已有有限重启与低内存回收，状态主要以一行文本展示，手动检查与组件检查合在一起。[证据 E13]

**建议。** 先增加定义跳转、导航返回/前进和文档大纲，再增加引用列表；按服务协商能力决定是否启用，Python 自带适配器若尚未提供方法就实际扩展并测试。服务启动/恢复提供详情和单独重试入口，清楚显示基础补全回退与语义就绪状态，保持有限自动重启。

格式化与符号重命名单独评估：优先调用已打包且确实支持的能力；缺少格式化器时要先离线打包和审计，不能调用云服务代替。多文件文本修改必须预览、校验版本并支持完整撤销，不能用全局字符串替换冒充语义重构。

**验收。** C/C++/Python/Java 分别验证跨文件、重载/作用域、Unicode 位置及外部只读源码导航。旧文档版本和旧项目请求被丢弃；语言服务失败仍可编辑和使用基础补全。跨文件修改未达到安全条件前不纳入发布功能。

### UX-14：更新更清楚，完整包更可控

**现状。** 当前 APK 为 **429,758,440 字节，约 409.8MiB**。更新已支持版本说明、大小、进度、取消、后台恢复和安全校验；下载前有实际空间检查，UI 可进一步提前展示所需空间。系统暂停统一显示等待网络，未呈现检查成功时间、速率或安装后版本结果。[证据 E14]

**建议。** 下载前显示文件大小、下载/校验所需空间、可用空间及可选的仅 Wi-Fi 下载。区分系统报告的等待 Wi-Fi、网络重试等原因；有足够样本后才估算速度/剩余时间，网络停顿时去掉失真的倒计时。显示“上次成功检查”与“本次检查失败”，重新打开应用后按实际安装版本确认升级结果，并提供一次性的版本说明入口。

先生成包体积构成报告，再评估重复资源、可压缩离线资产和 Android UI 代码裁剪。`material-icons-extended` 与 release 未启用 minify 是可评估项，但必须先量化其占比；不能预设它们能大幅降低包含大量原生工具链的总包体积。原生符号、JAR、Python 标准库和许可材料的裁剪必须逐项评估，保证四语言运行、调试、补全及对应源码交付完整。

**验收。** 弱网、断网、进程终止、下载取消、空间不足、安装权限拒绝、安装取消和实际升级后回归均有真实结果；不绕过签名、哈希、包名、ABI/SDK 或 versionCode 校验。只检查不自动下载，安装前保存且活动会话阻止安装。包体积优化前后执行离线四语言验收和原生审计，不承诺未经测量的缩小比例。

## 6. 验收、性能与发布门槛

每批实现只增加能验证行为的测试，优先复用现有 Workbench、OfflineIde、EditorAppearance、EditorPerformance 和更新/升级验证入口。不要把源码检索结果、构建成功或界面截图当作运行能力通过。

| 场景 | 必须核对的结果 | 证据要求 |
|---|---|---|
| 数据故障 | 写入失败、坏配置、取消导入、删除撤销后源码仍可恢复 | 故障注入结果、文件哈希、恢复前后对比 |
| 日常编辑 | 5～10 标签、1MiB 文件、中文组合输入、搜索和主题切换 | 实际操作录像/截图、时延采样、应用及子进程内存 |
| 输入与运行 | 四语言参数、交互/预置输入、EOF、超时、停止、生成文件 | 实际输出、退出原因、草稿与快照身份 |
| 调试与智能 | 四语言真实断点/单步/变量与跨文件补全；新增导航逐语言检查 | DAP/LSP 事件与真实源码位置，拒绝过期响应的结果 |
| 空间与长期使用 | 至少 100 次会话、导入失败重试、清理、后台返回 | 分类容量变化、清理清单和源码不变证据 |
| 更新 | 从较低 versionCode 下载新包，经系统确认升级，保留项目和设置 | 真实 GitHub 下载与系统安装流程；adb 覆盖安装另记 |
| 平台 | Android 10～17、4KiB/16KiB、厂商后台行为、外部 SAF | 标记设备/API/页大小；未覆盖的格子写待验证 |

继续使用规格中的性能目标：ARM64 / 6GiB 上输入到显示 P95 ≤50ms，暖补全 C/C++/Python ≤300ms、Java ≤500ms，1MiB 文件打开 ≤1.5s，Hello 启动 C/C++/Python ≤5s、Java ≤8s，停止 ≤2s。测量需说明冷/暖启动、文件大小、语言服务状态和采样范围；当前下一帧回调样本不能直接证明完整输入指标已达标。

发布前执行与修改相关的回归及故障测试，保留既有四语言核心覆盖；修改原生资源/包体积时重做 APK 审计。采用新 versionCode、原签名和新发布资产，保留 0.2.3 已冻结产物，不在同一标签下替换 APK。缺少广泛设备证据时准确声明兼容性范围，不将文档建议标为已完成。

## 7. 实施依赖与范围

推荐依赖顺序：先做 UX-01 保存状态，再做 UX-03 恢复导出及 UX-07 移动/删除；先做 UX-05 会话身份和保留规则，再做 UX-11 历史/产物入口。UX-02、UX-04 和 UX-10 的说明/触控修正可独立推进。多标签恢复、观察项恢复及项目管理统一设计元数据迁移，避免多个不一致的状态来源。

实现时按职责逐步将 `IdeScreen.kt` 中的首页、文件浏览、控制台与设置拆分，将 ViewModel 中保存、导航和会话交互梳理成可独立验证的组件。拆分跟随具体功能开展，不先安排大规模重写，不为整理目录引入新框架。

以下边界继续遵守：

- 全部编程运行资源随完整 ARM64 APK 离线交付；网络只用于已授权的更新流程。按语言在线下载组件或云端执行不作为本规划的缩包方案。
- minSdk 29、compile/targetSdk 37，release `debuggable=false`；无广泛存储权限，文件对外访问继续通过 SAF。
- 保持原子保存、不可变运行快照、独立进程和单活动会话。用户程序仍属同一 UID，不能宣传为恶意代码沙箱。
- 完整 pip/Maven/Gradle/CMake 依赖管理、Android/GUI 工程、Git/云开发、任意调试求值、条件/数据断点及 Python 专门多线程调试仍是规格中的延期项，需单独定义范围，不作为已承诺更新。
- UX-01～UX-14 已按用户授权加入 TASKS.md；只有取得对应实际产物证据后才更新验收状态。本页的“现状”保留原审查基线。
